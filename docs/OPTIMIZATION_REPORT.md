# LightNovelSelector 全面优化报告

审计日期：2026-08-01

审计基线：`main` 分支，开发版本 `2.1.0-dev.14`

稳定版本：`v2.0.2`

## 总体结论

项目已经从单文件 Python + 旧 WebView 形态，演进为 **WinUI 3 原生界面 + Python Sidecar 分类核心**。扫描预览、人工修正、文件移动、恢复日志、报告历史和撤销形成了完整闭环；本地与 GitHub 持续集成共同覆盖代码质量、文件安全、性能、界面构建和供应链边界。

当前源码没有追踪虚拟环境、构建目录、安装器、IDE 配置、真实小说、私人报告或旧 WebView 静态资源。旧架构通过不可变标签与独立分支保留，当前 `main` 只包含仍在维护的实现。

## 1. 清理了什么

- 将原先超过千行的 `classification.py` 收敛为兼容门面，文件发现、计划生成、安全校验、报告、恢复、移动执行和撤销分别进入独立模块。
- 移除当前源码中的旧 WebView 运行层、重复入口和历史 UI 资源；旧版保留在 `legacy-webview-final` 标签及 `legacy/webview-v2` 分支。
- 统一 Python 格式、类型和静态检查基线，清理无用 import、重复解析与无效兼容分支。
- 构建、测试、虚拟环境、IDE、缓存和安装器产物全部进入忽略规则；正式 `dist` 只由验证完成的构建流程生成。
- 依赖拆分为运行依赖与开发依赖，NuGet 和工具版本锁定，未发现已追踪的旧备份或废弃配置。

## 2. 优化了什么

### 识别与分类

- 建立统一 `BookIdentity`，集中表达标题、系列、作者、卷号、语言和标签。
- 加强中日英标题、全角字符、作者后缀、罗马数字、中文卷号、副标题和发布组噪声归一化。
- 用户明确保存的手动修正形成本地系列别名字典，后续精确命中时优先复用。
- 置信度使用统一保守标尺，并向界面和报告提供分类原因与证据，不只显示一个分数。
- EPUB 本地元数据与内容提示只在本机参与识别；联网查询不发送正文、完整哈希或报告。

### 文件处理与恢复

- 重复检测以快速签名分组，再用完整 SHA-256 确认，不会仅凭相同头尾和大小判断重复。
- 执行前复核分类根目录、源文件身份、大小、修改时间、目标目录和报告位置，拒绝路径越界、链接替换及扫描后变化。
- 目标冲突生成唯一安全名称，不覆盖已有文件；重复项和错误项默认跳过。
- 每次移动前持久化恢复意图，完整报告只在任务边界汇总；进程强制退出后可根据磁盘真实状态重建已移动记录。
- 撤销先预检整批文件，再逐项移动并复核后置状态；源和目标同时存在、同时缺失或内容状态变化时停止猜测。
- 分类历史按执行编号选择，界面不能传入任意报告路径；打开、导出和撤销都有独立路径复核。

### 稳定性与性能

- 在线来源具有独立限流、失败冷却、短期负缓存、健康统计、启停与优先级，不让单一服务拖慢整批扫描。
- 增量扫描缓存绑定文件 ID、大小、最后写入时间和可靠变更令牌；不具备可靠令牌时实时重算。
- 建立 10,000 文件冷扫描、热扫描、取消响应、内存和缓存复用预算；同一文件的重复解析与打开次数已减少。
- 本地基准中 10,000 文件热扫描从约 17.5 秒降到约 8.5 秒；CI 使用更宽预算，只拦截数量级退化。
- Sidecar 启动、请求、轮询、意外退出和重连具有明确状态；恢复连接后不会自动重跑扫描或文件移动。

## 3. 新增了什么

- 批量目录与同目录文件拖入、搜索、系列筛选、状态筛选和可见数量反馈。
- 标题、作者、卷号、语言、标签、置信度与分类依据详情。
- 单条或同系列手动修正、本地修正记忆和在线候选比较。
- 来源健康面板、来源启停与优先级设置。
- 重复与错误标记、分类历史、指定批次报告、导出与撤销。
- 快速取消、异常恢复入口、核心自动恢复一次和手动重新连接。
- SHA-256 清单、SPDX SBOM、构建信息、可选 Authenticode 签名和 GitHub 来源证明。
- 固定随机种子的 Unicode、EPUB/ZIP、协议与文件事务故障注入测试，以及真实 Sidecar 崩溃重连测试。

## 4. UI 改了什么

- 界面迁移为 WinUI 3 与 Windows App SDK，默认跟随 Windows 深浅色、动画和透明效果设置。
- 提供 Acrylic、Mica、实色三档窗口材质；高对比度或系统关闭透明效果时自动回退系统实色。
- 使用单层窗口级模糊与半透明卡片，减少重复模糊开销，同时保留清晰层级和文字对比度。
- 主工作台包含流程导航、目录导入、状态统计、筛选、结果表格、详情面板、活动报告与设置页。
- 首次启动提供一次性“先预览，再整理”引导，帮助入口可随时重新打开。
- 宽窗口并排显示详情；窄窗口使用同一详情控件的侧栏；低高度窗口可滚动到筛选、结果和确认区。
- 进入、页面切换、Toast、按压和进度采用短时非线性缓动；减少动态效果时取消非必要位移与缩放。
- 键盘快捷键、焦点循环、屏幕阅读器名称和不只依赖颜色的状态表达已纳入测试。

## 5. 发行与安装包

- Windows App SDK 改为只引用实际需要的组件，不携带未使用的 AI、ML、Widgets 与 DWrite 运行文件。
- 同条件发布输出从 221.51 MiB 降至 169.92 MiB；完整暂存目录约 180 MiB。
- 测量中的安装器从 72,482,903 字节降至 56,360,775 字节，减少约 22.2%。已发布的 `v2.0.2` 仍是优化前安装器，下一正式版本才会体现新体积。
- 正式构建在临时目录完成全部验证后才替换 `dist`，失败构建不会留下半套发布资产。
- 发布流水线固定 GitHub Actions 提交、NuGet 锁文件和 SBOM 工具版本，并要求标签、版本与中文说明一致。

## 7. 仍可继续的方向

以下事项不是当前功能缺陷，也不适合用未经验证的改动强行关闭：

1. **商业代码签名**：当前安装器仍显示未知发布者。构建入口已经完整，真正提升 SmartScreen 信任需要可信 CA 签发的代码签名证书及私钥，不能用自签名证书替代。
2. **正式发布开发成果**：`v2.0.2` 尚未包含本报告中的全部 `2.1.0-dev` 改进。应在版本冻结后通过标签流水线生成新安装器、SBOM、校验和来源证明。
3. **更多脱敏语料**：识别准确率下一阶段主要取决于社区提供的合法、脱敏真实命名样本与 EPUB 元数据变体，而不是继续堆叠未经证据支持的规则。
4. **更多平台包**：当前正式安装器以 Windows x64 为主；ARM64 需要独立构建、设备测试和发布资产预算，不能只修改项目平台列表。
5. **继续缩小大文件**：`application.py` 和 `MainPage.xaml` 仍较长，但职责已经通过 ScanSession、partial 和独立控件分散。后续只应在新增功能需要时继续提取，避免为了行数重构稳定流程。

## 8. 如何运行和测试

普通用户从 [GitHub Releases](https://github.com/chenhaoxiang05/LightNovelSelector/releases) 下载安装器，并按发布页核对 SHA-256。源码运行：

```powershell
.\run_winui.bat
```

核心验证：

```powershell
.\.venv-build\Scripts\python.exe -m pytest -q
.\.venv-build\Scripts\python.exe -m ruff check .
.\.venv-build\Scripts\python.exe -m mypy lightnovel_classifier.py lightnovel_sidecar.py lightnovel_selector tests
dotnet test native\LightNovelSelector.WinUI.Tests\LightNovelSelector.WinUI.Tests.csproj -c Release
dotnet build native\LightNovelSelector.WinUI\LightNovelSelector.WinUI.csproj -c Release -p:Platform=x64 -p:WindowsPackageType=None
```

完整安装器验证：

```powershell
.\build_winui.bat
```

开发环境、完整检查命令和发布流程见 [DEVELOPMENT.md](../DEVELOPMENT.md)，架构与安全边界见 [WINUI_ARCHITECTURE.md](WINUI_ARCHITECTURE.md)。
