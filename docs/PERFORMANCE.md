# 性能基准说明

LightNovelSelector 的性能门槛面向 Windows 大型本地书库。基准不使用用户文件、不访问网络，
也不把真实文件名写入报告；每次运行都在系统临时目录生成合成数据并在结束后清理。

## 覆盖范围

Python 基准使用 100 个批次目录和 10,000 个唯一 TXT 文件，按真实递归扫描路径执行：

1. 扫描开始 50ms 后请求取消，记录从发出请求到核心确认取消的延迟。
2. 删除取消阶段可能留下的临时缓存，执行完整冷缓存扫描。
3. 强制垃圾回收后，使用落盘缓存执行第二次扫描。
4. 记录计划数量、缓存复用率、缓存文件大小、墙钟时间和进程峰值工作集。

冷缓存扫描会经过目录发现、文件安全快照、快速签名、必要的完整 SHA-256、本地内容提示、
文件名解析和分类计划生成。热缓存扫描仍会核对文件 ID、大小、时间与 Windows ChangeTime，
不会为了跑分快而跳过文件变化验证。

WinUI 测试另外构造 10,000 条分类结果，连续执行文本搜索、状态筛选和系列选项去重排序。
该测试固定线性工作量和 2 秒宽松上限，用来发现意外的平方级算法或主线程阻塞。

## 当前预算

预算位于 `benchmarks/performance_budget.json`：

| 指标 | 上限或下限 |
| --- | ---: |
| 冷缓存扫描 | 不超过 180 秒 |
| 热缓存扫描 | 不超过 60 秒 |
| 热/冷耗时比 | 不超过 0.75 |
| 取消响应 | 不超过 2 秒 |
| 峰值工作集 | 不超过 768 MiB |
| 热缓存复用率 | 不低于 99% |

这些值是回归护栏，不是产品速度承诺。它们为不同 SSD、杀毒软件和 GitHub 共享 runner
保留了明显余量，但会拦截缓存失效、重复读取、非线性循环和内存失控等数量级退化。

## 本地运行

```powershell
.\.venv-build\Scripts\python.exe -m tools.benchmark_large_library `
  --files 10000 `
  --budget benchmarks\performance_budget.json `
  --output build\performance\large-library.json `
  --enforce
```

不加 `--enforce` 时仍会生成完整报告，但预算失败不会改变退出码，适合调查较慢的开发机器。
输出目录已由 Git 忽略。CI 会把关键指标追加到 GitHub Actions 任务摘要。

## 修改规则

- 优化前后必须在同一机器、相同电源模式和相同文件数下各运行至少一次。
- 不以牺牲完整哈希、路径边界、文件变化复核或取消检查换取速度。
- 预算变更必须说明硬件或工作负载变化，并附修改前后 JSON 指标。
- 新增文件格式或递归逻辑时，应先确认合成工作负载仍覆盖真实热点。
- 微小波动不作为优化结论；优先处理可由剖析定位、能稳定复现的热点。
